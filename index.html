Environment Details
Servers, OS, hardware specs
▼
Why first

You cannot plan an installation without knowing server count, OS, and specs. OneAgent needs admin access to each machine. RAM and CPU help size the monitoring impact.

Ask this

"Can you give us a full server inventory — hostnames, IPs, OS version, RAM and CPU per server?"

🔗
Network & Firewall
Ports, proxy, internet access
▼
Submit Day 1!

Firewall changes at banks take 3 to 5 days to approve. OneAgent needs port 9999 to ActiveGate, ActiveGate needs port 443 to Dynatrace cloud.

Ask this

"Who manages the firewall? We need to submit a change request immediately."

🔐
Access & Permissions
Admin rights, change management
▼
Banks are strict

Change Advisory Boards must approve every production installation. Missing this means no access on day one.

Ask this

"What is your change management process? Can we get a dedicated admin account?"

🌐
Application Architecture
.NET version, service flow
▼
Why

Dynatrace follows transactions through the system — but only if you know the architecture. Which APIs exist? What .NET version? Are there Windows Services running in the background?

Ask this

"Walk us through the request flow when a user clicks Login."

🗃
Database Details
SQL version, sensitivity
▼
Why

Dynatrace shows every SQL query — but some banks want sensitive data masked. SQL Server version determines which OneAgent sensor to use.

Ask this

"What SQL Server version? Any data sensitivity requirements around query capture?"

Question 04A
Alerting Configuration
The alarm bell — right person notified at the right time
Click any alert trigger to understand what causes it and why it matters
Critical — Immediate, any time
Application unavailable
Entire banking platform is down. Fires to on-call engineer AND IT manager via SMS within 60 seconds of detection.
Synthetic monitor failing
Robot user cannot log in — meaning real customers cannot either. Triggers before any complaint. Proactive detection at its best.
Error rate > 10%
More than 1 in 10 requests failing. Mass failure — fund transfers broken, logins failing. Needs immediate attention regardless of time.
Database unreachable
SQL Server cannot be reached. Zero transactions can complete — login, balance, fund transfer all fail simultaneously.
Fund Transfer API errors
The exact incident Finance House Bank already experienced. Dedicated alert because it directly involves customer money.
Warning — Business hours only
Response time degradation
APIs slow but not broken. Dynatrace AI learns the normal baseline and alerts if it jumps to 2x. Catch degradation before it becomes an outage.
CPU > 70% / Memory > 75%
Infrastructure under pressure. Investigate in business hours before it becomes a 2am critical incident.
Error rate 2 to 10%
Some requests failing but not a mass event. Could be a bug from a recent deployment or a specific API under stress.
Disk usage > 80%
At 100% disk, server stops writing logs and data. 80% gives time to clean up before disaster hits.
SQL queries > 2 seconds
A query that should take 100ms is taking 2000ms. DBA needs to investigate — likely missing index or data growth.
Info — Daily digest
New service detected
Dynatrace auto-discovered a new .NET service or Windows process. Could be legitimate or unauthorized — good to know either way.
OneAgent update available
Newer OneAgent version available. Sent to admin to plan an update during the next maintenance window.
Configuration change
Someone changed a Dynatrace setting. Important for audit trails in a bank — all changes must be tracked for compliance.
Baseline learning complete
Dynatrace finished its 7-day learning period. AI anomaly detection is now fully active and much more accurate.

Bonus Question
Troubleshooting Scenario
All servers visible — but NO user transactions appearing
❌

SYMPTOM: Hosts OK · CPU/Memory OK · OneAgent installed · BUT Distributed Traces = 0 · Services = 0 · Transactions = 0

Click each step to see the full diagnosis and fix
1
IIS Restart
#1 Most common — 80% of cases

OneAgent injects into .NET processes when they START. If IIS was running during install, it missed the injection window.

Fix: Run iisreset on all Web Servers as Administrator. Restart Windows Services too. Wait 5 minutes and check Distributed Traces.

2
Process Monitoring
Check second

Hosts > Web Server > Processes. Look for w3wp.exe. Should show "MONITORED". If "NOT MONITORED" — OneAgent sees the process but is not instrumenting it.

Fix: Check Settings > Excluded Processes. Remove w3wp.exe if listed.

3
Deep Monitoring
#2 Most common

Level 1 (Infrastructure) works immediately — that is why servers appear. Level 2 (Deep Monitoring) captures transactions and must be explicitly enabled.

Check: Settings > Deep Monitoring > .NET, ASP.NET, IIS all ON. Enable, save, then iisreset.

4
Generate Traffic
Confirm there is something to monitor

Open banking app > Login > Fund Transfer > check Distributed Traces within 60 seconds.

Trace appears = Dynatrace works, just needed traffic. No trace = continue to Step 5.

5
Read OneAgent Logs
Logs tell the truth

Location: C:\ProgramData\dynatrace\oneagent\log\

"Cannot connect to ActiveGate" = firewall issue. "Instrumentation skipped" = needs iisreset. "Deep monitoring disabled" = settings issue.

6
Environment / Zone
Easy to miss

Is OneAgent pointing to the UAT ActiveGate but you are looking in the Production Dynatrace tenant? The data is there — just in the wrong place.

Check: C:\ProgramData\dynatrace\oneagent\agent\config\ — the server= line must match the correct ActiveGate URL.

Summary
Key Takeaways

01
Discovery
Ask first, deploy second
Gather: server inventory, firewall details (Day 1!), admin access, app architecture, DB version, and define "success" before touching anything.
02
Deployment
Order is everything
Firewall > Env Separation > ActiveGate (both, HA) > OneAgent Web > App > SQL. Always UAT first. Always iisreset after install.
03
Validation
5 layers, all must pass
Infrastructure > SQL > Services > Transaction Tracing > Synthetic. Generate live traffic to confirm traces.
04
Alerting
Right person, right time
3 tiers: Critical (on-call, SMS, any time) > Warning (team, business hours) > Info (manager, daily digest).
05
Troubleshoot
Eliminate, don't guess
No traces? iisreset first (80% fix). Then check Deep Monitoring. Then read OneAgent logs.
